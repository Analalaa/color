# 仿色系统 Color Muse — 设计规格书

> **状态：** 已批准
> **日期：** 2026-05-13

---

## 1. 概述与目标

**目标：** 打造一个纯浏览器端的仿色工具，用户上传自己的图片，从图库中选择一张参考图，系统通过色彩迁移技术将参考图的色彩氛围映射到用户图片，输出颜色风格已被重新演绎的新图片。

**核心约束：** 纯前端，无需后端，所有计算在浏览器本地完成，数据不离开用户设备。

---

## 2. 技术架构

### 核心技术栈

- **前端框架：** 原生 HTML/CSS/JS（无框架依赖，便于学习和调试）
- **图像处理：** Canvas API（读取、绘制、像素操作）
- **并发处理：** Web Workers（防止大数据量处理时 UI 卡顿）
- **持久化存储：** IndexedDB（用户自定义参考图库）+ LocalStorage（用户偏好）
- **批量下载：** JSZip（客户端 ZIP 打包）
- **文件下载：** FileSaver.js 或原生 URL.createObjectURL

## 3. 功能模块详细设计

### 3.1 图片上传模块

**功能：** 支持用户将图片添加到画布

**交互方式：**
- 拖拽上传：拖图片文件到画布区域
- 点击上传：点击按钮打开文件选择器
- 支持格式：JPEG, PNG, WebP, BMP

**技术实现：**
- FileReader API 读取文件为 DataURL
- Canvas 绘制图片并获取 ImageData 像素数据
- 支持多图批量添加（进入批量处理模式）

**状态：**
- 空状态：显示"拖拽图片到此处或点击上传"
- 加载中：显示进度
- 已加载：显示图片缩略图预览

### 3.3 参考图库模块

**内置预设风格（内置图库）：**
按色彩主题分类，每类 5-8 张参考图：
- 日系小清新（低饱和度、高亮度、冷色调）
- 欧美电影感（高对比度、高饱和度、暖色调）
- 复古胶片（颗粒感、褪色效果、色偏）
- 赛博朋克（霓虹色、高对比、紫绿为主）
- 莫兰迪（低饱和灰调、柔和）

**自定义图库：**
- 用户可上传自己的参考图
- 上传后存入 IndexedDB
- 支持删除已上传图片
- 缩略图网格展示，每张可点击选中

**交互：**
- 点击图库中某张参考图 → 自动执行色彩迁移 → 结果显示在画布
- 支持多图批量选择，依次处理

---

### 3.4 色彩迁移引擎

#### B 方案：统计颜色迁移（Histogram Transfer）— 主体方案

**算法原理：**
1. 将图片从 RGB 色彩空间转换到 LAB 色彩空间（人眼感知更接近）
2. 分别提取源图（用户图片）和参考图的 L、a、b 通道直方图
3. 对源图每个通道做直方图匹配（Histogram Matching），使其分布接近参考图
4. 将处理后的 LAB 转回 RGB 输出

**实现步骤：**
- RGB → LAB 色彩空间转换（线性变换 + gamma 校正）
- 计算源图和参考图的 LAB 直方图
- 构建累积分布函数（CDF）
- 对源图每个像素做映射
- LAB → RGB 反转换

**参数控制：**
- 迁移强度滑块（0% ~ 100%）：0% = 原图，100% = 完全迁移

#### A 方案：ICC 色域映射 — 进阶能力

**触发方式：** 用户可切换算法，切换后重新计算

**实现思路：**
- 通过 Web Color Space API（Chromatic Adaptation）实现 ICC profile 转换
- 或通过 ColorMatrix 对 RGB 空间做线性变换近似
- 注意：纯前端 ICC profile 处理较复杂，V1 先聚焦 B 方案

---

### 3.5 预览对比模块

**功能：** 显示原图与迁移后效果的对照

**模式：**
- 左右分屏：原图 | 迁移后
- 上下分屏：原图（上方）| 迁移后（下方）
- 滑块对比：拖动滑块左右移动，对照原图和结果

**交互：**
- 点击"原图/结果"切换显示模式
- 点击"1:1"查看实际像素尺寸

---

### 3.6 下载与批量处理模块

**单个下载：**
- 点击"下载"按钮，将当前结果保存为 PNG/JPEG
- 文件名格式：`colormuse_YYYYMMDD_HHmmss.png`

**批量处理：**
- 在画布中批量添加多张用户图片（同一参考图）
- 勾选"批量模式"，选择要处理的图片
- 点击"批量应用"，依次对每张图片执行迁移
- 处理完成后，弹出下载选项：
  - 逐个下载（自动触发多个下载）
  - 打包下载（JSZip 打包为 ZIP，一次下载）

## 5. 数据存储设计

### IndexedDB Schema

**数据库名：** `colormuse_db`

**Object Store 列表：**

| Store 名 | 类型 | 用途 |
|---------|------|------|
| `reference_images` | 对象存储 | 用户自定义参考图（二进制） |
| `processing_history` | 对象存储 | 处理记录（可选，V1 可跳过） |

**`reference_images` 结构：**
```json
{
  "id": "uuid",
  "name": "文件名",
  "blob": "Blob 对象",
  "thumbnail": "DataURL 缩略图",
  "createdAt": "timestamp"
}
```

### LocalStorage

| Key | 类型 | 用途 |
|-----|------|------|
| `colormuse_preferences` | JSON | 用户偏好（最后使用的算法、迁移强度、布局状态） |

## 8. 测试策略

### 核心算法测试（histogram-transfer.js）

- **测试用例：** 已知输入图片 + 参考图，验证输出直方图分布与参考图趋近
- **边界测试：** 全黑图、全白图、灰度图、极高饱和度图片
- **性能测试：** 4K 图片（3840×2160）的处理时间，目标 < 3 秒

### UI 交互测试

- 拖拽上传是否正常工作
- 参考图选择后是否正确触发迁移
- 下载按钮是否生成有效图片文件
- 批量模式是否正确执行

---

## 9. 成功标准

1. 用户上传任意图片，选择任意参考图，能在 3 秒内看到色彩迁移结果
2. 结果图片色彩氛围与参考图主观接近（可接受轻微偏差）
3. 无服务器依赖，所有数据留在本地
4. 支持批量处理 ≥10 张图片的批量打包下载
5. 内置图库 5 个风格，每个风格 ≥5 张参考图

---

## 10. 已知约束与降级策略

| 约束 | 降级方案 |
|------|---------|
| 大图处理慢 | Web Workers 异步处理，进度条提示 |
| 浏览器 Canvas 限制 | 限制单图最大 8000×8000 |
| IndexedDB 存储上限 | 提示用户清理自定义图库，单图建议 < 10MB |
| A 方案 ICC 实现复杂 | V1 仅支持 B 方案，A 方案作为后续里程碑 |
